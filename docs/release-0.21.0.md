# 0.21.0 本地候选：P0 接入演练

这是本地开发分支的隔离候选，不是公开 Release，也不替换正式 0.20.0。

## 操作流程

1. 使用虚构品牌和商品，保存并确认可公开的事实。
2. 进入「AI 测试 → 接入演练」，选择自然发现或带资料问答；预览可见本次发送内容。自然发现不包含商品资料，并拒绝问题中显式出现品牌、别名、完整商品名、SKU 或官网域名。它不保证识别所有暗示。
3. 创建使用 `.invalid` 地址的模拟任务；配置任务额度和工作区 UTC 每日模拟额度。额度以模拟单位和次数计，不是人民币费用。
4. 继续任务后完成基线、候选生成、静态页面检查，在原有内容页人工审核候选；返回任务后，另行确认当前目标及稿件版本的模拟发布。
5. 查看模拟回执、回读及复测；发布响应未知时先对账。可恢复模拟发布前版本，首次发布回滚至未发布。
6. 导出包含任务、请求、额度记录、回执、页面检查和审核稿件的 ZIP。实际网络、模型和公开发布次数均为 0。

## 自动化边界

- 本流程只能运行内置 fixture。未提供真实 CMS、平台账号、API 或网络执行能力；实际功能接入需单独验收与授权。
- 基线和复测重放相同模拟回答，差值不代表优化成效；带商品资料的问答与消费者自然发现分开标注。
- 原生 worker 仅在应用进程运行时推进已恢复的任务。退出时停止，重开及备份恢复后暂停；运行中检测到超过 2 秒的墙上时间间隔或时钟倒退时保守暂停 P0 任务，并非系统睡眠事件监听。较短睡眠、时钟跳变及检查与执行之间的竞态可能漏检或误暂停；真实系统睡眠尚未验收，也不是系统后台定时任务。
- 模拟故障包括限流一次、发布响应未知、回读正文不一致和 robots 阻断。重试有次数上限；未知发布不得盲重试。
- 原生稿件审核与模拟发布批准是两个独立步骤。审核前修改稿件，必须重新审核，并按模拟额度重新检查预览。审核节点完成后再修改稿件，须取消旧任务并新建演练，重新审核和批准；不能沿用旧批准。
- 全局停止和每日预算针对本接入演练，不宣称控制其他页面的手动模型调用。

## 数据与兼容

源码版本 0.21.0，数据库 schema 10。新增任务与策略参与严格校验、加密备份及恢复；升级 schema 9 文件前保留 `before-p0-v10-*.sqlite3` 快照。任务、账本与模拟回执持久化在本地 SQLite。

不要用 0.20.0 打开 schema 10。若将来正式升级需要回滚，应退出应用，同时恢复升级前 App 与完整资料目录；只替换 App 不够。本轮独立候选使用独立 Bundle ID，正式资料不会升级。

## 许可与验证

继续遵守 AGPL-3.0-only、GEOFlow 来源署名及第三方许可证；未引入新依赖。

自动化单元测试、构建与隔离原生验收的实际结果记录在本轮交付报告中。真实模型、真实公网、账号、公开发布、消费者推荐效果和 Apple 公证不属于本轮验证。
